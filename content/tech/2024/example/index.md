> 这是一篇编辑示例，不是真实的2024年记录。你可以直接把它改成自己的第一篇技术。示例日期仅用于展示年份。

## 1. 找到这个文件

在项目文件夹中打开：

```text
content/tech/2024/example/index.md
```

用 VS Code、Codex 或其他纯文本编辑器打开 `index.md`，修改并保存即可。`.md` 表示 Markdown 文本文件。

## 2. 修改文件顶部的信息

文件最上方两条 `---` 之间是文章信息。保留两条分隔线，修改它们之间的字段，例如：

```yaml
---
title: "我的第一篇技术"
date: 2024-06-15T12:00:00+08:00
draft: false
description: "用一两句话介绍这篇文章。"
tags: [学习, 记录]
---
```

- `title`：文章标题，会显示在列表和正文顶部。写好后去掉“待填写（编辑教程）”。
- `date`：实际写作或发布日期。列表按这个日期归入年份，并按时间倒序排列；**文件夹名称本身不决定页面上的年份**。修改年份时，也建议把文章文件夹移到对应年份下。
- `draft`：`false` 表示正常显示；`true` 表示草稿，默认预览和正式构建会隐藏它。当前示例使用 `false`，因此可以在网页看到。
- `description`：文章简介，技术栏目的卡片会显示它。
- `tags`：文章标签，用逗号分隔。可以替换“示例教程”，不需要标签时写 `tags: []`。

日期晚于当前时间的文章默认不会显示，请填写真实且不晚于今天的日期。

## 3. 用正文替换这份教程

第二条 `---` 后面全部是正文。删除本教程，换成你自己的文字即可。下面是一份可以照着写的结构：

```markdown
## 问题与目标

我想解决的问题是……

## 过程与思考

记录一个问题、解决思路、实现步骤和验证结果。

- 一条值得记下的细节
- 另一条想法或步骤

## 接下来

下一步我想……
```

常用写法：`## 小标题`、`**加粗**`、`- 列表项`、`[链接文字](https://example.com)`。两段文字之间留一个空行。

## 4. 添加图片或代码

把图片放在本篇文章的 `index.md` 旁边，例如 `photo.jpg`，再在正文写：

```markdown
![图片说明](photo.jpg)
```

请先放入真实图片，再添加引用。不要保留不存在的图片链接。

技术卡片的封面可以命名为 `cover.png` 或 `cover.jpg`，也放在 `index.md` 旁边。页面会自动读取；没有封面时显示文字占位，不需要修改模板。

技术内容中的代码可以用三个反引号包围，并注明语言。例如，下面展示的四个反引号只是为了在教程中完整显示示范，你实际只需复制内部的三反引号代码块：

````markdown
```python
print("Hello, world!")
```
````

## 5. 保存与预览

本地预览服务运行时，保存文件后网页通常会自动刷新。如果没有刷新，手动刷新浏览器即可。

如果服务没有运行，在项目根目录打开终端，执行：

```sh
.tools/hugo server -D
```

`-D` 会让本地预览包含草稿。打开终端提示的地址，进入“技术”，找到对应年份即可查看。修改本地文件不会自动发布到 GitHub；以后配置好 GitHub Pages 后，需要把修改提交并推送到仓库，等待部署完成。

## 6. 再添加一篇

在同一个年份目录下，新建一个不同名字的文件夹，例如 `my-second-post`，把这篇 `index.md` 复制进去，再修改标题、日期、简介和正文。英文小写字母、数字和短横线组成的文件夹名比较方便维护。

```text
content/tech/2024/
├── example/
│   └── index.md
└── my-second-post/
    └── index.md
```

`example` 是示例文章的网址组成部分，正式写作前可以改名。发布后尽量保持文件夹名稳定，避免已有链接失效。
